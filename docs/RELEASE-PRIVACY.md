# Release privacy audit / 发布隐私核对

Updated for 1.1.0 on 2026-10-21. This is a source/template release, with fictional demo/test content. It is not a copy of the author's live data directory.

| Included / 已包含 | Excluded / 未包含 |
|---|---|
| Reusable Python backend and original web UI | Live messages, memories, todos, intentions and run artifacts |
| Generic configuration defaults and setup documentation | Personal `config.json`, local SQLite databases, logs and Markdown exports |
| Generic application adapter, schema example and import helper | Actual application IDs, school evidence, email contents, connector inboxes and personal deployment notes |
| Synthetic demo and test fixtures with example identities | Feishu App Secrets, OAuth access/refresh tokens and account stores |
| A screenshot rendered from fictional demo data | Private work screenshots and real conversation/chat/thread IDs |
| MIT license and public GitHub project links | Codex authentication files, private keys and machine-specific user paths |

## Verification

- The public tree is selected through Git; release ZIP/tar.gz files are built with `git archive` from that tree.
- `scripts/audit_release.py` checks tracked files for runtime data, common credential patterns, real-looking chat/user IDs, machine-user paths and broken documentation links. It is a focused check, not a universal secret detector.
- The UI screenshot is generated by `server.py --demo`; its JPEG contains no EXIF, XMP, IPTC or comment metadata. Names and work items shown there are fictional.
- Downloaded release assets are compared to local source bundles by SHA-256. The initial v1.0.0 assets were also checked; they do not contain personal runtime data.
- Commit authorship uses the public GitHub username and a GitHub noreply address. The repository owner, copyright attribution, public commit identifiers and repository links remain public by design. These identify the public software project; the release is not anonymous.
- Private `runtime.local.json`, `LOCAL-DEPLOYMENT.md`, `scripts/sync_personal.py` and machine-specific launchers are excluded. The public helper is `scripts/sync_applications.py` and reads each user's own configuration.

## When you use the framework

Your own live records and CLI credential stores are created locally only after setup/use. They are ignored by Git and are not part of these source archives. Future users must keep them out of their own commits/backups they intend to publish. Analysis sends selected account content to their authenticated Codex model service; see [SECURITY.md](../SECURITY.md).
